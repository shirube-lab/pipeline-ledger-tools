# work7 — 「重要管路」の 4 条件を台帳から機械判定してみる

下水道管路マネジメントのための技術基準等検討会の「中間整理」(令和 8 年 1 月)は、
事故時の社会的影響の大きさで管路を **重要管路** と **枝線** に区分し、重要管路に
4 つの条件を挙げています(印刷ページ p.11)。

1. 下水処理場～処理場直前の最終合流地点までの管路
2. 流域下水道の管路
3. 管径２ｍ相当以上の大口径管路
4. 緊急輸送道路下、軌道下、河川下の管路

このツールは 4 条件を 1 つずつコードにして、公開台帳(半田市オープンデータ)に
当てたときに **何が判定でき、何が判定できないか** を出力します。抽出できた管路
だけでなく、判定に足りなかった情報も同じレポートに残すのが目的です。

> **注意**: 中間整理は検討途上の文書で、法令の条文に「重要管路」の語はありません
> (e-Gov の法令全文検索で法律・政令・省令いずれも 0 件)。改正下水道法
> (令和 8 年法律第 65 号)のうち維持管理状況の公表義務などの本体部分も未施行です。
> このツールの出力は特定の管路を公式に重要管路と判定するものではありません。

## 実行

```bash
python data/handa/setup_data.py       # 初回のみ(台帳データの展開)
python data/env/setup_env_data.py     # 初回のみ(条件 4 の軌道下で N02 を使う)
python work7-important-pipes/extract_important_pipes.py
```

N02 が無い場合、条件 4 の軌道下だけがスキップされ、他の条件はそのまま計算されます。

## 出力(`output/`)

| ファイル | 内容 |
|---|---|
| `summary.json` | 4 条件それぞれの判定結果と、判定できなかった理由 |
| `cond1_trunk_runs.csv` | 条件 1 を有向グラフで解いた結果(末端ごとの遡上区間) |
| `cond3_large_diameter.csv` | 条件 3 で拾えた管きょ(口径・管種・施工年度・延長) |
| `cond4_road_candidates.csv` | 条件 4 の候補(両端のマンホールが市道以外の管理者) |
| `cond4_rail_pipes.csv` | 条件 4 のうち軌道下(N02 鉄道データの中心線と交差する管きょ) |
| `pipe_sizes.csv` | 全管きょの口径・延長(記事の図の入力) |

## 各条件の実装と、その限界

### 条件 1 — 処理場～最終合流地点

「処理場より上流すべて」ではなく「処理場と、その直前で最後に合流する地点との間」
と読みます。有向グラフでは「下流端から遡り、入次数が 2 以上になる節点で止める」
という単純な歩行になります。

判定できないのは **どの末端が処理場か** です。配布データに処理場のレイヤはなく、
流域関連公共下水道の場合、処理場も最終合流地点も流域下水道(都道府県)の側に
あります。ツールは全末端について歩行を解き、分布として出力します。

流向は台帳の属性ではありません。work3(記事 #10)と同じく、地盤高 − 土被り − 口径
による管底高の近似から推定しています。この補正を入れると下流端の数が
139 → 301 に増える点も `summary.json` に残しています(近似が末端を作っている)。

連結成分も出力します。汚水管きょは 83 成分に分かれ、延長の大きい成分は処理分区と
おおむね対応します(処理分区ごとに別々の接続箇所で流域下水道の幹線につながるため)。
ただし 1 対 1 ではなく、複数分区が 1 成分にまとまる例(最大成分は 4 分区)と、
1 分区が複数成分に割れる例(北浦処理分区は 4 成分)の両方があります。スナップ許容差を 1cm(既定値)〜2m で振っても最大成分は 68% 前後のままで、
スナップ精度の問題ではありません(スイープの結果は `summary.json` に出力します)。

### 条件 2 — 流域下水道の管路

台帳のマンホールが持つ「下水道区分名」の値をそのまま報告します。管理主体の境界が
データの境界になっているため、関連市町の台帳では「該当なし」が正しい答えです。

### 条件 3 — 管径 2m 相当以上

唯一、属性フィルタで完結する条件です。ただし中間整理は「相当」の換算規則を
定義していません(第 3 回資料の段階では「管径２ｍ以上」で「相当」は無し)。
大阪市は全国特別重点調査で断面積換算を公表していますが、国の統一ルールとしては
確認できません。

そのうえ配布データの管きょ属性は 5 列だけで、口径の列名は **「管径１(mm) 径/幅」** —
円形の径と矩形の幅を兼ねています。断面形状も内空高さもありません。よって
単一の数字ではなく、しきい値 1500〜2500mm のスイープとして出力します。

> ここで「台帳に無い」と書いているのは、すべて **配布されたオープンデータの範囲** の
> 話です。市の台帳システム本体が持つ列の全部とは限りません。

### 条件 4 — 緊急輸送道路下・軌道下・河川下

3 つに割れます。

**軌道下は実装できます。** 国土数値情報の鉄道データ(N02)が 2020 年(令和 2 年)以降
CC BY 4.0 で、軌道の中心線を線データで持っているためです。中心線と交差する
管きょを「軌道を横断する管」として拾い、バッファ幅(5/10/20m)による感度も
併記します。バッファは軌道敷幅の代用で、鉄道用地界ではありません。

**緊急輸送道路下は、商用利用できる公開データが見つかりませんでした**
(2026-09-01 時点)。国土数値情報 N10 は使用許諾条件が「非商用」、G空間情報
センターのミラーも同じ約款、愛知県・半田市は PDF のみ。東京都・岐阜県・山口県は
自前で商用可ライセンスの GIS データを公開しており、「出している自治体と
出していない自治体がある」状況です。

**河川下も不可です。** W05(河川データ)は「非商用」かつ 2006〜2009 年度基準の
まま更新がなく、基盤地図情報の「公共施設の境界線(河川区域界)」は 13 項目に定義は
あるものの、ダウンロードサービスの提供対象に見当たりません(2026-09-01 時点)。

そこで台帳側の絞り込みも用意しています。マンホールの **道路管理者名** の列を使い、
両端が市道以外の管理者である管きょを候補として残します。**判定ではなく絞り込み**
です(市道が指定される場合も、県道が指定されない場合もあります)。道路管理者名が
空欄の端点を持つ管きょの本数・延長も併記し、結果が下限であることを明示します。

## 交換標準(素案)との対応

ここで「配布データに無い」とした項目の一部は、国総研の交換標準(素案)に定義があります
(work5 の `schema/nilim_draft_schema.json` 参照)。いずれも多重度 [0..1] の任意項目で、
器があることと値が入ることは別です。

| 足りなかったもの | 素案の属性 |
|---|---|
| 断面形状・内空高さ(条件 3) | 管きょ: 断面形状 / 内法幅 / 内法下幅 / 内法高(p.22) |
| 緊急輸送道路の指定(条件 4) | マンホール: 緊急輸送路(p.21) |
| 流向(条件 1 の前提) | 管きょの関連役割: 上流/下流マンホール番号(p.23) |
| 幹線の識別(参考) | 管きょ: 幹線流域(p.22)— 流入先の幹線名であって、最終合流地点は特定できない |

素案でも埋まらないもの: **処理場と管きょの接続関係**(下水道管路パッケージの地物は
マンホール・管きょ・公共ます・取付け管の 4 つ。参考情報の地震防災マップパッケージに
「防災関連重要地物」(形状・名称・注記、p.67)があるので位置は置けるが、管きょとの
関連役割は定義されない)、**鉄道用地界**、**河川区域**。
